## 1. 项目定位与身份

### 1.1 产品定位

- 产品的核心价值是让角色像“住在桌面上”一样陪伴用户。
- 主要目标用户是《床下有罐钱》的原作粉丝。
- 角色表现尊重原作设定，允许补充不扩展、歪曲原设的合理日常表现。
- 第一版追求功能不多但可以真实、长期运行的完整产品，不是一次性技术演示。
- 第一版只发布当前角色，不在第一版支持多个角色同时运行。

### 1.2 正式名称与标识

- 中文显示名称：`《床下有罐钱》非官方桌宠`。

## 2. 第一版产品范围

### 2.1 自主行为

- 无人操作时，角色在待机、行走、休息和少量特殊动作之间自主切换。
- “休息”不依赖新素材：角色停止移动并继续播放待机动画，只延长停留时间。
- 程序启动时，角色出现在鼠标所在屏幕的底部；不恢复上次退出位置。
- 角色平时在当前屏幕底部活动。
- 角色可以在以下有明确原因的场景暂时离开底部区域：
  - 活跃模式下偶尔接近鼠标。
  - 被用户拖到其他位置后短暂停留，再自行返回底部。
- 角色不随机探索整个屏幕，避免无缘由地遮挡工作内容。
- 活跃模式下，角色偶尔走到鼠标附近，但停在安全距离外，不直接覆盖鼠标位置。
- 自主行为的概率、持续时间、移动速度和各动画速度使用内部参数，在原型阶段调优；第一版设置界面不暴露这些底层参数。

### 2.2 安静、活跃与暂停

- 提供“安静”和“活跃”两种活动模式，首次启动默认为安静模式。
- 安静模式仍播放待机动画，但不主动接近鼠标，也不主动显示气泡。
- 活跃模式允许自主移动、偶尔接近鼠标，并按气泡设置选择的频率显示气泡。
- 第一版不再增加低、中、高等额外行为强度档位。
- 另提供“暂停”：冻结移动和自主行为，但仍可使用右键菜单。
- 暂停只对当前运行周期有效，不保存；下次启动恢复已保存的安静或活跃模式。

### 2.3 角色状态与记忆

- 第一版不做饥饿、心情、亲密度、养成数值或隐藏角色状态。
- 不保存角色位置、互动记录、最近行为或长期角色记忆。
- 用户设置需要持久化；“不保存角色记忆”不包括软件设置。
- 隐藏状态不保存。用户主动启动程序时，角色必须出现。
- 锁屏、桌面会话不可见或系统进入睡眠时，暂停动画和自主行为；恢复会话后继续，不补算离开期间的行为。

### 2.4 不进入第一版的功能

第一版明确不包含：

- 开机自启动。
- 音效和角色语音。
- AI、聊天模型、本地模型或外部 AI API。
- 联网、自动更新、遥测或自动上传诊断数据。
- 系统通知。
- 全局快捷键。
- 用户可安装的角色包、行为脚本或插件接口。
- 多角色同时运行或同一角色多开。
- 自定义崩溃上报、minidump 收集和自动重启。
- 全屏应用检测及全屏时自动隐藏。用户自行使用暂停、隐藏或关闭置顶。

## 3. 用户交互

### 3.1 单击与拖动

- 没有正在进行的连续对话时，单击角色根据当前行为从可用动作、表情和短句中给出随机反馈。
- 即使气泡设置为关闭或被安静模式抑制，单击仍至少提供动作或表情反馈。
- 用户操作立即中断自主行为；交互结束后再返回自主循环。
- 拖动角色时保持当前画面，不切换为不存在的“被提起”姿势或新动画。
- 松手位置靠近屏幕底部时，角色留在该处继续活动。
- 松手位置远离底部时，角色短暂停留后自行返回底部活动区。
- 用户把角色拖到另一块显示器后，该显示器成为新的当前屏幕；角色不会自主跨显示器。
- 多显示器目前没有实际测试条件。上述跨屏行为仍实现，但第一版标为未实测、best-effort，接受 Issue 和 PR，不宣称已通过验收。

### 3.2 投喂

- 通过角色右键菜单选择“投喂”。
- 第一版投喂直接使用现有吃冰淇淋动画，不做食物列表、库存、获取或消耗系统。
- 投喂时按程序内置概率偶发播放“冰淇淋掉落”情节。
- 掉落概率不提供用户设置。
- 当前投喂动画结束前，忽略新的投喂请求，不排队、不重播，也不引入冷却状态。

### 3.3 右键菜单、托盘与隐藏

角色右键菜单是主要控制入口，第一版包含：

- 投喂。
- 安静／活跃切换。
- 暂停／继续。
- 设置。
- 隐藏。
- 关于。
- 退出。

其他规则：

- 明确选择“退出”后直接结束，不再弹确认框。
- 托盘只作为备用入口，必要功能不能只存在于托盘中。
- 托盘可用时，提供显示角色、模式切换和退出等常用控制。
- 程序必须是单实例。已经运行时再次启动，应唤回并显示现有角色，不创建第二个实例。
- Linux 原生 GNOME 可能没有托盘，因此应用菜单的二次启动是正式唤回通道。
- Linux 用户没有安装应用菜单入口时，再次运行同一个 AppImage 也会唤回现有角色。
- Windows 托盘是正常恢复通道；免安装 ZIP 不主动创建开始菜单或桌面快捷方式。

### 3.4 窗口输入与桌面表现

- 角色可见像素接收交互，透明区域穿透鼠标输入，不能形成不可见的矩形阻挡区。
- 默认始终置顶，设置中允许关闭。
- 角色窗口不出现在任务栏，并尽量不进入普通 `Alt+Tab` 窗口切换列表。
- 第一版不提供“固定到所有工作区／虚拟桌面”功能，也不显示相关设置。Linux 产品路径运行在 XCB/XWayland 上，EWMH 工作区语义在目标桌面环境中并不稳定；Windows 同样没有公开稳定的对应 API。该项不是桌宠核心能力，不为此分别接入桌面环境私有接口。

## 4. 气泡与角色文案

- 角色以动作和表情为主，少量台词气泡为辅，不做高频陪聊。
- 气泡设置提供关闭、低频和正常频率。
- 气泡默认低频；安静模式完全抑制气泡，切换到活跃模式后才按所选频率出现。
- 活跃模式下气泡可以偶尔自主出现，单击反馈也可以触发气泡。
- 普通单句气泡数秒后自动消失；精确持续时间在原型阶段调优。
- 气泡沿用原作 demo 的极简方向：半透明黑色对话框搭配像素风字体，与原作和角色素材保持统一。
- 对话框表情布局固定采用已审核原型 A“表情嵌入面板”：表情完整嵌在面板左侧，文字位于右侧，中间使用一条低对比度竖分隔线；表情与文字共同构成一个紧凑信息块。
- 面板保持近直角的半透明黑色矩形，只使用低对比度单像素边界，不加投影、发光、装饰标题栏或额外角色名标签；翻页提示位于面板右下角。
- 选定时的本地审核原型为 `Temp/dialogue-bubble-designs/variant-a-embedded.html`。`Temp/` 不受 Git 跟踪，因此正式实现以本文冻结的结构规则为准；浏览器原型只用于视觉参照，具体透明度、内边距、字号和 Qt 字体栅格参数仍需在正式原型阶段实测微调。
- 不把较长文案一次性全部展示。存在多个语义节拍的文案由项目预先人工分页，点击后逐页推进，并允许女主表情随页面切换。
- 分页和表情映射是内容数据的一部分，不在运行时按字数、标点或文件名自动生成。
- 所有显示台词的页面都必须同时显示该页经过人工审核的对应表情；该组合是桌宠的招牌表现，不仅用于长对话，也覆盖普通短句。

### 4.1 连续对话交互

- 连续对话采用快速打字效果，每个字符 `28 ms`。该值由 2026-08-27 的 Qt 原型审核在 `20–30 ms` 区间内确定。第 14.4 节在 `1.1.0` 把打字速度解冻为设置项；`28 ms` 继续作为默认值，本条记录的原型审核结论不因此失效。
- 当前页仍在打字时，第一次点击立即补全当前页；再次点击才进入下一页。
- 进入下一页时，同时切换到该页预先指定的表情。
- 最后一页显示完成后，再次点击结束对话。
- 连续对话不自动翻页。用户持续 `20 s` 没有操作时，对话自动结束；下次重新触发同一段对话时从第一页开始。
- 自主闲聊和单击反馈允许选中多页文案。此时按本节的连续对话规则显示：需要点击翻页，**不套用普通单句气泡的自动消失时长**，无人操作时由 `20 s` 超时结束。第 4.5 节中写成两页的闲聊文案据此进入随机气泡池。
- 显示对话期间暂停角色的自主移动和自主行为，但继续播放当前朝向的待机动画；对话结束后重新进入自主循环。
- 对话期间仍允许拖动角色。拖动不推进台词，对话框跟随角色移动，松手后继续显示当前页。
- 点击对话框或点击角色都可以补全／推进台词；在角色上形成拖动手势时只执行拖动，不推进台词。
- 对话框和角色以外的透明区域继续穿透输入，不能因为对话出现而形成不可见的大矩形点击区域。
- 对话期间打开右键菜单不会结束当前对话。

### 4.2 事件优先级与冲突处理

发生内容或行为冲突时，正式代码必须按以下顺序统一调度：

1. 退出／隐藏。
2. 用户主动投喂。
3. 当前连续对话。
4. 单击反馈。
5. 自主闲聊。

具体规则：

- 用户选择隐藏时立即结束当前对话并隐藏角色；退出时立即结束进程，两者都不保留待恢复的对话页面。
- 连续对话期间抑制新的随机闲聊；单击只补全或推进当前对话，不另外触发随机反馈。
- 用户选择投喂时结束当前对话并立即进入投喂事件。
- 用户触发的单击反馈可以替换正在显示的自主闲聊。
- 互相冲突的对话和行为不排队，低优先级事件被抑制或替换后不会在稍后补播。
- 优先级由统一的行为／事件调度逻辑实现，不能分散为各功能互相覆盖的临时判断。

### 4.3 人设与写作边界

- 女主的核心形象是呆呆的、神经比较大条、喜欢吃零食，自然形成可爱感。
- 原作台词主要作为语气参考，只直接收录已经逐条确认、且脱离原场景后仍能成立的部分。
- 新增文案保持短、直白和自然；可以有天真的歪理、跳跃的因果和对零食的积极反应。
- 不把角色写成刻意撒娇、恋爱陪伴或甜腻卖萌的形象。
- 不加入网络热梗、成人化表达、原作没有的新经历或复杂背景设定。
- 原作 demo 台词与项目新增文案分组保存，逐条标记来源和触发场景，不能混为同一来源。

### 4.6 表情素材使用边界

- 每个显示页面使用上表中经过人工审核的明确表情，不从全部表情素材中随机挑选。
- `shadow.png` 是为了保持原作图标库完整而收录的特殊剧情素材，不进入第一版常规表情池，也不参与任何随机表情选择。

## 5. 设置、首次启动与关于

### 5.1 设置窗口

第一版提供小型 Qt Widgets 设置窗口。设置项为：

设置规则：

- 第一版只提供简体中文界面，设置中不提供语言选择项。可翻译是工程约束而非设置项：界面文本一律走 `tr()`，不硬编码，资源结构保持可加载翻译文件。
- 第一版不提供工作区／虚拟桌面设置；程序遵循当前窗口管理器的默认工作区行为。
- 修改后立即生效并保存，不设置额外“应用”阶段。
- 提供“恢复默认设置”。
- 使用各系统标准用户配置目录，不把配置写在 EXE、AppImage 或当前工作目录旁边。
- 显示倍率一律使用**整数倍率**和最近邻采样，不提供小数倍率、连续缩放或平滑插值。源像素因此始终落在整数屏幕像素上，边缘完全清晰。
- `1.5×` 曾于 2026-08-27 经 Qt 原型审核后采用，同日撤回。撤回理由是它在锐利度上被整数档完全支配：系统 DPI 缩放会再叠加一层，实际生效的是 `项目倍率 × 系统 DPR`，只有该乘积为整数时像素才完全清晰；`1.5×` 只在 `200%` 系统缩放下满足，而那一档 `1×` 与 `2×` 本来就满足。它没有任何一个配置是靠它才能成立的，却要求角色窗口与像素命中掩码全部支持小数倍率。
- 系统 DPI 缩放的叠加规律见上一条。例如 `150%` 系统缩放下 `2×` 得到整数的 `3` 倍，而 `1×` 得到 `1.5` 倍。实测见 `docs/WindowsFeasibilityResults.md` 第 3 节。程序不因此改写用户所选倍率。
- 第一版设置固定提供 `1×`、`2×`、`3×` 三档，并至少验收 `1×` 和 `2×`。三档已于 2026-08-27 在 KDE Plasma + XWayland 上完成运行时切换实测。

## 7. 移动方向与动画映射

屏幕坐标约定为：`x` 向右为正，`y` 向下为正。

现有素材按左上、左下、右上、右下四个斜向使用：

| 速度方向 | 逻辑方向 | 待机素材 | 跑动素材 |
| --- | --- | --- | --- |
| `dx < 0, dy < 0` | `up-left` | `assets/character/idle-up-left.png` | `assets/character/run-up-left.png` |
| `dx < 0, dy > 0` | `down-left` | `assets/character/idle-down-left.png` | `assets/character/run-down-left.png` |
| `dx > 0, dy < 0` | `up-right` | `assets/character/idle-up-right.png` | `assets/character/run-up-right.png` |
| `dx > 0, dy > 0` | `down-right` | `assets/character/idle-down-right.png` | `assets/character/run-down-right.png` |

方向映射遵循以下规则：

- 运行时使用显式动画映射，不根据原始文件名推断方向。
- 角色停止后保持最后移动方向，播放该方向的待机动画。
- 纯水平移动默认使用正面方向：向左为 `down-left`，向右为 `down-right`。
- 纯垂直移动沿用上一次的左右朝向。
- 方向判断使用速度死区与切换滞后，避免速度在零附近波动时频繁转身。
- 不对素材做水平镜像；头发和包具有左右差异，使用作者提供的四套原画。

## 8. 支持平台与窗口后端

### 8.1 跨平台原则

- 项目目标为 Linux 与 Windows 双平台兼容。
- 核心行为、交互、菜单、设置和配置格式在两个平台保持一致。
- 窗口、托盘、工作区等系统集成功能允许使用不同实现或明确降级。
- 自主移动、透明、拖动、像素级穿透、置顶和唤回属于核心能力；这些能力在正式支持环境中失败时，不能宣称该环境受支持。
- 可以先分别发布测试候选包，但首个正式版本 `1.1.0` 必须同时包含并支持 Linux 与 Windows。

### 8.2 Linux

- Linux 正式实现使用 Qt XCB 后端，运行于现代 Wayland 桌面提供的 XWayland 路径。
- 正式启动入口主动选择 XCB；XCB 不可用时显示错误，不能静默回退到 Qt 原生 Wayland。
- Qt 原生 Wayland 后端不属于第一版支持范围。
- 原生 X11 登录会话只做 best-effort，不作为正式发布门槛。
- KDE Plasma 是正式支持目标。
- 当前已验证配置为 Fedora 44、KDE Plasma 6.7.4、Wayland 会话、XWayland 24.1.13、Qt XCB。
- GNOME 是目标环境，但当前没有本地测试条件。发布前先用公开候选包征集发布时当前稳定版 GNOME 用户测试：
  - 至少一名用户在一套精确配置上完整通过检查表后，该配置才列为已验证。
  - 若 `1.1.0` 正式发布前没有合格测试结果，GNOME 只能标为实验性／未验证支持，接受 Issue 和 PR，不能声称已正式验收。
  - 原生 GNOME 无 AppIndicator 扩展是主要测试路径；安装扩展后的托盘行为属于附加兼容测试。
- 每个正式候选版以发布当时的 KDE/GNOME 稳定系列为测试基线，不永久固定当前 Plasma 6.7 或 GNOME 50。
- README 和发行说明分别列出“支持目标”和“实际验证配置”，不笼统宣称所有发行版或所有 KDE/GNOME 组合均已验证。
- niri 暂不支持。程序在已知不支持环境中显示明确警告，但允许用户以 best-effort 模式继续运行。

#### XCB 不可用时的报错通道

Qt 在 `QApplication` 构造期间加载平台插件，失败时直接终止进程，程序拿不到控制权。因此报错必须在构造之前处理：

- `QT_QPA_PLATFORM` 只设为单值 `xcb`，禁止使用 `xcb;wayland` 这类候选列表，避免 Qt 自行回退。
- 构造 `QApplication` 之前先做原生连接探测（`xcb_connect` 是否成功）。
- 探测失败时不以 XCB 构造 `QApplication`，改用 Wayland 后端只创建一个说明原因的错误对话框，并以非零退出码结束。该回退只用于报错，不进入运行状态，不属于被禁止的静默回退。
- Wayland 后端同样不可用时（例如纯终端环境），错误写入 stderr 与本地日志。
- 探测通过但 XCB 插件仍加载失败时（例如缺少 `libxcb-cursor`），Qt 会终止进程。为此在构造 `QApplication` 之前安装 Qt 消息处理器，把该致命信息写入本地日志，保证这种情况至少留下可查记录。

### 8.3 Windows

- 正式支持 Windows 11 x86-64。
- Windows 10 1809+ 仅做 best-effort；不把已经结束常规支持的 Windows 10 作为正式验收目标。
- 第一版不提供 Windows ARM64 预编译包；ARM64 用户可自行编译。
- 优先使用 Qt；Qt 无法满足窗口细节时，允许通过窄平台接口调用 Win32 API。
- 正式版本使用 Windows GUI 子系统，不弹控制台窗口；诊断信息写本地日志。
- 独占全屏检测与自动隐藏不进入第一版，见第 2.4 节；Windows 侧不另立例外。

### 8.4 平台适配边界

- 平台相关能力放在窄接口中，不把条件编译散落到动画、行为和角色逻辑中。
- Windows 单实例使用命名 mutex 判断唯一实例，再用 Qt 本地 IPC 发送“唤回”请求。
- Linux 单实例使用唯一 Unix socket 和 Qt 本地 IPC，并处理遗留 socket。
- 不仅依靠 Windows `QLocalServer` 充当唯一实例锁。
- 使用 `QStandardPaths` 和 `QSettings` 统一管理各平台配置。

## 9. 技术栈与构建

### 9.1 语言、Qt 与模块

- C++20。
- Qt Widgets，不引入 Qt Quick/QML。
- 开发 API 基线为 Qt 6.11。
- 当前 CI 精确锁定 Qt 6.11.2。
- Qt 6.11.3 或后续版本发布后不自动漂移；先通过 Linux XCB 与 Windows 双平台探针和自动测试，再显式升级锁定版本。
- 生产模块为 `Core`、`Gui`、`Widgets`、`Network`；Linux 构建另加 `DBus`。
- 测试额外使用 `Test`。
- `Network` 只用于 `QLocalServer`／`QLocalSocket` 等本地 IPC，不赋予程序联网功能。
- `DBus` 只在 Linux 上用于第 2.3 节要求的会话状态检测（锁屏、解锁、挂起与恢复），不用于其他用途。Windows 构建不链接该模块，改用 Win32 会话通知接口。

### 9.2 构建系统

- 使用 CMake、Ninja 和统一的 `CMakePresets.json`。
- Linux 与 Windows 共用工程结构和构建入口，不维护独立 Visual Studio 工程或 qmake 工程。
- 测试使用 Qt Test，并由 CTest 统一运行。

### 9.3 GitHub Actions

- 编译、自动测试和打包主要在容器或 GitHub Actions 中执行，避免污染宿主机；真实宿主桌面测试由项目所有者亲自执行或由明确的社区测试者执行。
- 每次 push 和 pull request 都构建 Linux 与 Windows，并运行可自动化测试。
- 两个平台使用同一个工作流和同一个精确 Qt 版本。
- Windows CI 固定 `windows-2022`、MSVC 2022、CMake 和 Ninja，不使用会迁移的 `windows-latest`，也不维护 MinGW 构建。
- CI 使用经过审查并锁定完整提交 SHA 的 `install-qt-action`／aqt 路径从公开 Qt 存档取得精确版本，避免依赖 Qt 账号密钥；工作流打印最终 Qt 版本。
- 具体选用 `jurplel/install-qt-action`，锁定 `48d3ad6db93f3627c8ee7a0454bc6f3744f7e730`（v4.3.1）。
- aqtinstall 不使用 PyPI 发布版，改由该 Action 的 `aqtsource` 从 Git 安装，锁定 `16db45a70b5905ad596941b223469bc86a56901e`。原因是 Qt 官方存档在 `6.11.0` 改为按架构分目录，aqtinstall 在 PyPI 上的最新发布版 `3.3.0` 只认旧结构，装不了 `6.11.x`；修复已合入上游 master 但尚未发布。aqtinstall 发布 `3.4.0` 后改回固定版本号。
- Linux AppImage 先在 Ubuntu 22.04 runner 验证。若 Qt 6.11 预编译包存在 glibc 兼容问题，则改为缓存从官方源码构建的相同 Qt 版本。
- 正式发布二进制只由打标签后的 GitHub Actions 生成，不上传开发机手工构建的正式包。

### 9.4 Windows 前置适配顺序

- 正式产品代码推进前，先把现有 Qt 窗口探针适配到 Windows。
- GitHub Actions 负责 Windows 编译、自动测试和打包。
- 项目所有者直接在 Windows 环境测试 GitHub Actions 产出的实际包，而不是另外测试本地临时构建。
- Windows 探针需要覆盖透明、移动、拖动、穿透、置顶、焦点、任务栏／`Alt+Tab`、混合 DPI 和生命周期行为。

### 14.2 设置结构

- 设置窗口分为四组：行为、对话、外观、窗口与桌面。第 5.1 节的四个既有设置项分别归入对应组，取值与默认值不变。
- 每组内分「普通」与「高级」两层。高级是组内的展开区，不是独立页面：`idleMinMs` 这类原始数值脱离它所细化的档位就没有意义，与档位并列才可读，「按组恢复默认」也才成立。
- 普通层只提供命名档位，不出现毫秒、像素或百分比。高级层提供原始数值。
- 高级层使用面向用户的简体中文名称和自然单位，不把 `idleMinMs` 之类的内部变量名直接显示给用户。秒级时长以秒显示，保存和运行时再转换为毫秒。
- 对所有由档位驱动的设置，**实际参数是唯一真相来源**，配置文件不另存一份“当前预设”。选择预设时把该预设对应的参数写入实际参数；界面根据实际参数反向匹配，完全匹配时显示对应档位，否则显示“自定义”。
- 高级层的控件形式按参数性质区分：
  - 单值、有界的参数（移动速度、各动画帧时长、打字速度）配滑块与数字框，双向绑定。滑块用于快速粗调，数字框用于精确输入；正在执行的行为不因拖动而被重算或打断。
  - 百分比参数（休息概率、接近鼠标概率、单击附带台词概率、自主闲聊触发概率）同样配滑块与数字框。取值天然有界，且滑块本身表达了「这是一个概率」。
  - 成对上下限（待机、行走、休息三组时长）**只提供数字框**。两个滑块互相顶越会引入额外的越界处理策略，而这正是本节要求成对校验的地方；区间滑块不是 Qt 内置控件，为此自制控件超出 `1.1.0` 范围。
  - 滑块永远与数字框成对出现，不单独提供滑块。精确输入必须始终可用。
- “恢复默认设置”扩展为“按组恢复”与“全部恢复”两级。两种操作执行前都必须确认：分组确认框明确显示组名，全部确认框明确说明影响全部设置；取消确认不修改运行时值或持久化值。
- 第 5.1 节的其余规则继续适用：只提供简体中文界面、不提供语言选择项、界面文本一律走 `tr()`。
- 设置值按行为、对话、外观、窗口四个领域分组；设置界面只产生设置变更，不直接读写 `QSettings`，各行为与对话模块也不接触持久化后端。应用层的设置控制逻辑统一负责校验、向领域模块应用配置和自动保存。

### 14.4 对话参数

普通层：

| 设置项 | 档位 | 说明 |
| --- | --- | --- |
| 说话频率 | 关闭／低／中／高 | 由第 5.1 节的关闭／低频／正常三档扩展而来 |
| 单击台词概率 | 低／中／高 | 驱动唯一参数 `clickTextChancePercent` |
| 打字速度 | 慢／正常／快 | 驱动 `typingMsPerChar`，见下 |

- **说话频率必须实际控制自主闲聊。** `1.0.0` 候选实现中该设置只区分“关闭”与“非关闭”，低频与正常对自主闲聊没有差别，闲聊是否发生完全由活动节奏决定（活跃模式下每次待机结束若未进入休息或接近鼠标，即请求一次闲聊）。`1.1.0` 必须引入独立的时间调度，使各档位产生实际差异。
- 第 4 节「角色以动作和表情为主，少量台词气泡为辅，不做高频陪聊」继续成立。说话频率的最高档也不得使桌宠变成高频陪聊。
- **单击台词概率必须与说话频率解耦。** `1.0.0` 候选没有独立的单击台词设置；`1.1.0` 只保留一个有效参数 `clickTextChancePercent`，不再保留按说话频率二选一的两个概率，也不从说话频率读取该值。低档默认 `20%`，中档与高档见下方已冻结的档位映射表。
- 自主闲聊由独立的时间调度器驱动，不依赖待机、行走或休息之间的状态切换。每轮完整间隔结束时只进行一次概率判定；未触发、角色正忙或请求被更高优先级事件抑制时，不排队也不补播，直接重新开始下一轮完整间隔。安静模式和“关闭”档停止自主闲聊调度。
- 说话频率的“关闭”档由自主闲聊触发概率 `0%` 表达，不另存启用标志；概率为 `0%` 时界面显示“关闭”，间隔值暂不生效。低／中／高档分别写入各自的间隔与非零概率，未完整匹配时显示“自定义”。
- **“关闭”只写概率，不动间隔。** 用户从“关闭”切回任一档时间隔由该档重新写入；在高级层单独把概率改成 `0` 时，原间隔保留在配置里，界面显示“关闭”。

高级层与当前默认值：

| 参数 | 默认 | 建议输入范围 | 备注 |
| --- | --- | --- | --- |
| `chatterMinIntervalMs` 自主闲聊最小间隔 | `120000` | `10000`–`1800000` | **新参数，`1.0.0` 候选不存在** |
| `chatterChancePercent` 自主闲聊触发概率 | `30` | `0`–`100` % | **新参数，`1.0.0` 候选不存在** |
| `clickTextChancePercent` | `20` | `0`–`100` % | 单击附带台词的唯一概率参数 |

- **打字速度解冻。** 第 4.1 节的 `28 ms` 由 2026-08-27 的 Qt 原型审核确定，`1.1.0` 将其开放为设置项，`28 ms` 继续作为默认值。原型审核结论作为默认值的来源记录保留，不被撤销。

| 单击台词 `clickTextChancePercent` | — | `20` | `45` | `70` |

### 14.6 窗口、桌面与应用生命周期

| 层级 | 设置项 | 说明 |
| --- | --- | --- |
| 普通 | 始终置顶 | 已有，不变 |
| 普通 | 应用菜单入口的安装与移除 | 第 5.2 节要求提供该操作且位置留待实现时确定，`1.1.0` 落位于本组 |

- 应用进程的生命周期由应用层显式管理，不由 Qt 的“最后一个普通窗口关闭”规则决定。
- 角色、气泡、设置和关于窗口都是应用拥有的窗口。关闭设置或关于窗口只关闭该辅助窗口，不得连带退出桌宠；再次打开时必须正常显示，并且同一种辅助窗口同时只允许一个实例。
- 用户从右键菜单、托盘或其他正式退出入口明确选择“退出”，是正常结束应用进程的唯一用户操作。初始化失败等致命错误仍可按错误路径退出。

### 14.7 保持不开放的项

以下各项在 `1.1.0` 明确不开放为用户设置，理由随附：

- **冰淇淋掉落概率**（`dropChancePercent`，默认 `15`）。第 3.2 节写明「掉落概率不提供用户设置」，该句没有「第一版」限定，属于对功能本身的决策而非版本推迟。
- **气泡渲染参数**（第 4.8 节全部取值）。这些是已冻结的外观决策，`src/ui/BubbleMetrics.h` 与 `tests/ui/tst_bubblelayout.cpp` 共同保证头文件与本文一致；开放它们等于撤销一条外观冻结，不属于本版范围。
- **连续对话无操作超时**（`idleTimeoutMs`，第 4.1 节 `20 s`）。保持冻结。
- **工作区／虚拟桌面设置**（第 3.4 节、第 5.1 节）。排除理由是 EWMH 工作区语义在目标桌面环境不稳定且 Windows 无公开稳定 API，该理由未被新的事实推翻。
- **语言选择**（第 5.1 节）。可翻译是工程约束而非设置项。
- **`bottomTolerancePx`**（默认 `8`）。判定阈值，不是体验参数。
- **`timeJumpThresholdMs`**（默认 `2000`）。第 2.3 节「恢复会话后继续，不补算离开期间的行为」依赖该阈值成立，用户改动会破坏会话恢复语义。

### 14.8 持久化、生效与兼容

- 第 5.1 节“不设置额外‘应用’阶段”继续成立，但 `1.1.0` 把**接收设置**、**作用于行为**与**落盘**分开。合法值变化后立即进入运行时配置；正在执行的行为持有启动时的配置快照，不重算、不跳转、不被中途打断，从下一次对应行为开始使用新值。
- 具体生效边界固定如下：待机、行走和休息时长在下一次进入对应状态时生效；移动与返回速度在下一次开始对应移动时生效；休息、接近鼠标等概率在下一次行为选择时生效；返回延迟与安全距离在下一次对应拖放或接近鼠标行为生效；自主闲聊参数在下一轮调度生效；单击台词概率在下一次单击生效；打字速度与单页自动消失时间在下一次对话生效；动画帧时长在下一次启动对应动画时生效；活动模式在当前行为结束后生效。
- 显示倍率和始终置顶属于直接窗口属性，没有“下一次行为”，修改后立即生效。
- 设置仍然自动保存且没有“应用”按钮，但运行时接收与落盘分开：滑块在 `sliderReleased`、数字框在 `editingFinished` 时写入一次，键盘或其他连续变更可以经短去抖后写入。一次滑块拖动或尚未完成的数字输入不得逐次同步配置文件。
- `1.1.0` 的新设置结构从 `schemaVersion = 1` 开始。没有 schema 的 `1.0.0` 候选配置视为开发期数据，不迁移旧字段，按 `1.1.0` 默认设置重新建立配置。
- 读取高于当前程序支持范围的 schema 时，使用安全默认值启动并记录警告，不自动覆盖原配置；这条规则用于避免降级运行破坏未来版本的数据。
- `sanitized()` 扩展为支持成对约束。当前实现只做单值回落，无法处理「最小值大于最大值」这类关系错误；三组时长上下限必须成对校验并回落。
- 配置文件仍是用户可编辑的普通文件，可能被手工改坏或被上一版程序写坏。任何非法值都回落到默认值并继续启动，不中断运行。
- 继续使用各系统标准用户配置目录，不写在 EXE、AppImage 或当前工作目录旁边。

### 14.9 不得扩张的边界

- 第 2.3 节继续完整成立：不保存角色位置、互动记录、最近行为或长期角色记忆；隐藏状态不保存；暂停只对当前运行周期有效。
- 设置项数量增加不得成为把运行时状态写入配置的理由。`src/core/Settings.h` 中“本结构不得扩张到那些内容”的约束在 `1.1.0` 依然有效，新增的全部是用户设置，没有一项是角色状态。
- `1.1.0` 不引入饥饿、心情、亲密度或养成数值（第 2.3 节）。行为参数可配置不等于角色获得内部状态。

### 14.10 验收范围相对第 11 节的调整

以下调整只适用于 `1.1.0`，是对第 11.3 节与第 11.4 节的显式调整。第 11 节原文不改写，本节各条也不自动延续到后续版本。

- **Windows 的连续三小时运行放宽。** 第 11.3 节「正式验证环境各连续运行至少 3 小时」在 `1.1.0` 只对 KDE 正式验证环境强制。Windows 11 仍须完成检查表的全部项目，但不要求连续运行三小时。理由是 Windows 验收需要项目所有者切换系统，而 `1.0.0` 候选已在 Windows 上完成过一次三小时运行且未报告崩溃、卡死或持续资源增长。
- 放宽只针对运行时长。Windows 的锁屏／睡眠／显示器恢复、Explorer 重启、四档系统缩放、显示倍率和明确退出等检查项一项都不减少。
- `1.1.0` 之后若要重新要求 Windows 的长期运行数据，由当时的版本决策另行规定，不视为本条自动失效。
- **性能不设数值门槛。** 第 11.4 节「在首个正式候选版前冻结 CPU、内存、启动时间和长期增长预算」在 `1.1.0` 不执行为数值门槛：三小时运行是观察手段，不是自动判定的通过条件。启动时间、CPU、内存和长期增长仍按检查表如实记录，**占用是否可接受由项目所有者在验收时判断**，结论以「通过／不通过」写入验收记录与 Release 说明，不换算成固定预算数字。
- 该判断属于第 11.4 节的发布阻断规则范畴：项目所有者判定资源占用不可接受时，按「影响核心交互的问题」阻止发布；判定可接受时不因缺少数值门槛而拖延发布。
- 不写数值门槛的理由与第 11.4 节原意一致——原条款要避免的是凭空指定预算。当前只有单机单环境的实测数据，把它固化成跨环境门槛同样属于证据不足；改为如实记录加人工判定，比冻结一个只在一台机器上成立的数字更诚实。

### 14.11 档位取值的冻结来源

第 14.3 至 14.5 节的三张档位映射表冻结于 `1.1.0` 开发计划的人工检查点 A
（`docs/Plans/DevelopmentStatus-1.1.md`），环境为 KDE Plasma（Wayland），
被测产物是提交 `d03d46d` 上 `Package candidates` run `33146976117` 的
Linux AppImage。项目所有者实测全部档位后判定手感可接受，原型取值原样冻结，
未作调整。

- 这些数值此后是决策基线的一部分，`src/core/SettingsPresets.cpp` 是其唯一实现处；
  两者不一致时以本节为准。
- 冻结的是**档位到参数的映射**，不是参数本身的可调范围。用户仍可在高级层把任一
  参数改到第 14.3 至 14.5 节列出的输入范围内的任意值，此时按第 14.2 节显示“自定义”。
- 后续版本要改动这三张表，按修订流程另立条目，不在本节原地覆盖。

同一次检查点记录的资源占用结论：项目所有者判定**通过**。依据是一次 5 分钟采样
（30 个样本，采样中穿插互动、设置修改、暂停与恢复），常驻内存 `16.1`–`16.3 MB`
无增长趋势，线程数恒为 `2`。按第 14.10 节，该结论以「通过」记入验收记录，不换算
成预算数字。更长时间的连续均值测量放在发布阶段进行；本次的 5 分钟采样不替代
第 11.3 节对 KDE 的连续运行要求。
