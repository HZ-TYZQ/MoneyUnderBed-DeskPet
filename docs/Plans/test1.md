# 第一版可行性探测计划

日期：2026-08-26

状态：已完成；结果见 `docs/FeasibilityResults.md`

## 1. 目的

本次探测只验证 C++/Qt 是否具备桌宠所需的基础窗口与动画能力，不实现产品功能，也不建立正式产品架构。

测试需要回答：

1. Qt 能否正确显示透明、无边框的像素角色窗口？
2. 精灵表裁切和动画播放是否清晰、稳定？
3. 程序能否自主改变顶层窗口的位置？
4. 用户能否拖动角色窗口？
5. 鼠标穿透能否可靠开启和恢复？
6. 置顶与浮动窗口在 niri 下是否有效？
7. 原生 Wayland 和 XCB/XWayland 的行为差异是什么？

## 2. 可证伪假设

核心假设：

> 原生 Wayland 可能禁止自主设置顶层窗口位置；相同的 Qt 程序通过 XCB/XWayland 运行时应当能够自主移动。

辅助假设：

- Qt 能在 Wayland 和 XCB 下正确绘制透明像素窗口。
- 现有横向精灵表可以按 `69 x 111` 单帧尺寸稳定裁切和播放。
- Qt 的系统拖动接口至少能在一个后端工作。
- 整窗鼠标穿透可以在运行时开启，并由定时器恢复。
- `WindowStaysOnTopHint` 的实际效果取决于 niri 和所用平台后端，需要实测而不能仅根据 Qt API 推断。

## 3. 原型边界

探针代码放在：

```text
Temp/qt-window-probe/
```

它不进入正式 `src/`，也不作为产品架构起点。角色 PNG 从外部路径加载，不编译进 Qt `.qrc`。

原型只包含：

- 一个透明角色窗口。
- 一个精灵表播放器。
- 固定距离的窗口往返移动。
- 系统拖动与手动拖动回退探测。
- 可自动恢复的鼠标穿透。
- 输入穿透测试所需的底层点击计数窗口。
- 屏幕、平台、窗口位置和帧间隔日志。

不包含角色状态机、随机行为、对话、投喂、托盘、设置或存档。

### 执行环境边界

- 依赖查询或安装、CMake 配置、编译和自动化测试尽量在 Distrobox `dev-fedora` 内执行。
- 不在宿主机安装项目依赖或编译工具。
- 宿主机图形测试由用户亲自执行，探针只提供可复现命令、日志和人工检查表。
- 容器构建产物只写入已被 Git 忽略的 `Temp/qt-window-probe/build/`。

## 4. 测试用例

| 用例 | 验证内容 | 通过标准 |
| --- | --- | --- |
| `build` | Qt/CMake 工具链 | CMake 配置、编译和启动成功 |
| `render` | 透明窗口与像素绘制 | 无背景矩形、无异常黑白边、像素不模糊 |
| `animate` | 精灵表裁切 | 帧序正确，无越界、明显跳动或持续计时异常 |
| `move` | 程序自主移动窗口 | 至少一个后端实际往返移动 300 像素，位置日志同步变化 |
| `drag` | 用户拖动 | 至少一个后端可平滑改变窗口位置 |
| `input` | 鼠标穿透 | 穿透期间底层窗口收到点击，恢复后角色重新收到点击 |
| `topmost` | 置顶/浮动 | 激活普通终端或浏览器后角色仍保持在其上方 |
| `screen` | 屏幕与缩放 | 正确输出屏幕、可用区域和设备像素比 |

每个用例独立运行，不在一个自动流程里同时改变多个窗口特性。

## 6. 各用例方法

### 6.1 构建

- 使用 CMake 配置 Qt Widgets 工程。
- 使用 Ninja 编译。
- 开启常用编译警告。
- 先运行 `screen` 用例，验证程序能启动并加载指定 Qt 平台插件。

### 6.2 透明与渲染

- 创建透明、无边框、置顶的固定尺寸窗口。
- 从现有待机精灵表裁切一帧 `69 x 111`。
- 默认以 2 倍整数倍率绘制。
- 禁用平滑缩放，观察透明边缘、裁切和高 DPI 清晰度。

该项需要人工观察截图或屏幕，程序日志只能证明素材加载和绘制路径执行成功。

### 6.3 动画

- 按精灵表宽度除以 69 得出帧数。
- 每 100 ms 前进一帧。
- 记录实际帧间隔的最小值、最大值和平均值。
- 连续运行至少 60 秒，观察是否出现越界、抖动、卡住或资源增长。

### 6.4 自主移动

- 记录运动起点。
- 以固定步长向右移动 300 像素，再向左返回。
- 每次同时记录请求位置、`QWidget::pos()` 和 `frameGeometry()`。
- 比较 Wayland 与 XCB 下请求值和实际报告值是否一致。

如果 Wayland 忽略位置请求而 XCB 正常，则核心假设成立，不判定 Qt 整体不可行。

### 6.5 用户拖动

- 鼠标左键按下时优先调用 Qt 的系统拖动接口。
- 记录接口是否被平台接受。
- 如果不被接受，尝试基于全局鼠标位置的手动移动，并单独记录回退结果。
- 不把回退成功与系统拖动成功混为同一个结论。

### 6.6 鼠标穿透

- 在角色窗口下方创建一个带点击计数器的普通测试窗口。
- 先验证角色能收到点击。
- 运行 3 秒后自动开启整窗穿透。
- 在穿透阶段点击角色覆盖区域，底层计数应增加。
- 运行 8 秒后由定时器关闭穿透。
- 再次点击时角色应重新收到点击。

必须使用定时器恢复，避免开启穿透后无法通过角色自身接收关闭操作。

### 6.7 置顶

- 显示角色后依次激活终端和浏览器。
- 切换普通工作区并记录行为。
- 全屏窗口之上的显示不作为首轮硬性通过条件，但需要记录。

### 6.8 屏幕信息

启动时记录：

```text
Qt version
platformName
XDG_SESSION_TYPE
DISPLAY
WAYLAND_DISPLAY
screen name
screen geometry
available geometry
device pixel ratio
window flags
requested/reported position
```

默认日志只记录关键状态变化。定位平台插件问题时再启用：

```bash
QT_LOGGING_RULES="qt.qpa.*=true"
```

## 7. 判定规则

### 可行

- 至少一个后端支持透明、动画、拖动、穿透和自主移动。
- 像素渲染没有明显失真。
- 没有崩溃、持续资源增长或严重计时异常。

### 条件可行

原生 Wayland 无法自主移动，但 XCB/XWayland 通过其他必要测试。

此时只得出“Qt 可行，Linux 自主移动需要 XCB/XWayland”的技术结论，不延伸为产品功能决策。

### 暂不可行

如果 XCB 下也无法自主移动或透明窗口严重异常：

1. 确认实际加载的是 `xcb` 平台插件。
2. 检查 niri 浮动规则和 XWayland 集成。
3. 在另一个 X11 环境复测。
4. 区分 compositor、Qt 平台插件和探针代码的责任边界。

在形成新假设前不更换框架，也不叠加平台特殊补丁。
