日期：2026-08-27

状态：待项目所有者审核。审核通过后按阶段执行；任何阶段未通过退出门时，不提前叠加下一阶段功能。

## 1. 目标与边界

本计划负责把已经冻结的第一版产品范围转化为可以逐项执行、测试和验收的工程任务。计划不重新讨论产品功能，也不以实现困难为由删除 `docs/Decisions.md` 中的功能。

第一版完成的判定不是“能显示角色”，而是同时满足：

- Linux KDE Plasma + Qt XCB/XWayland 正式环境通过核心桌面能力验收。
- Windows 11 x86-64 通过核心桌面能力验收。
- 冻结的角色行为、互动、投喂、对话、菜单、设置、单实例、生命周期和诊断功能全部完成。
- 自动测试、打包产物自检、三小时真实桌面测试和许可文件检查全部通过。
- GitHub Actions 生成的同一份候选产物经过人工验收后直接发布，不以本地临时构建替代。

第一版不实现 `docs/Decisions.md` 第 2.4 节排除的功能。

## 2. 执行原则

### 2.1 决策与变更

- `docs/Decisions.md` 是唯一产品需求基线。本计划和旧提案与其冲突时，以该文件为准。
- 已冻结功能不能在开发中静默降级或删除。发现技术阻断时停止对应阶段，记录证据并回到项目所有者决策。
- 尚未冻结的数值和视觉参数先通过原型或测量取得证据，再写回 `docs/Decisions.md`。
- 每个阶段只在退出门通过后进入下一阶段，避免后续功能建立在未验证的平台假设上。

### 2.2 问题处理

- 先复现原始失败，追踪控制流和平台行为，再形成可证伪假设。
- 优先修复根因，不以重建窗口、重复调用、定时补救或平台特例掩盖失败。
- 连续多次尝试失败或补丁开始累积时停止编辑，重新检查上游组件和原始假设。
- `Temp/` 中的探针可以快速试验；未经验证的探针代码不得直接复制为正式架构。

### 2.3 开发环境

- Linux 依赖取得、配置、编译和自动测试默认在 Distrobox `dev-fedora` 中执行。
- 构建目录使用仓库内被忽略的目录或容器临时目录，不向宿主安装开发依赖。
- Linux 宿主图形测试由项目所有者执行。
- Windows 编译和打包由 GitHub Actions 执行；项目所有者测试 Actions 产出的实际 ZIP。
- `Reference/` 和 `Temp/` 不进入正式构建，也不成为 CI 必需输入。

### 2.4 每阶段提交质量

- 新增纯逻辑同时新增 Qt Test 单元测试。
- 新增资源同时更新资源清单、许可证信息和资源完整性测试。
- 新增平台能力同时提供自动可检查部分和真实桌面人工检查项。
- 编译警告按错误处理；确需例外时只在最窄目标或源文件范围说明原因。
- 每阶段结束运行 `git diff --check`、相关单元测试和当前可用的打包自检。

## 4. 目标工程结构

正式产品不从 `Temp/qt-window-probe` 原地扩建。由于 `Temp/` 被 Git 忽略、GitHub Actions 无法读取其中源码，阶段 1 会把审查后的最小探针抽取到受跟踪但与产品隔离的 `probes/window/`；`Temp/qt-window-probe` 继续保留为本地可行性实验记录。通过阶段 1 后建立下列职责边界：

```text
CMakeLists.txt
CMakePresets.json
cmake/
probes/
  window/       # 受跟踪的跨平台窗口探针，不链接产品代码
src/
  app/          # QApplication 前后的启动、组装与命令行入口
  core/         # 平台无关状态、事件调度、行为与数据模型
  character/    # 动画定义、精灵表、移动与方向映射
  dialogue/     # 台词数据、分页、表情映射与打字状态
  platform/     # Linux XCB / Windows 的窄平台接口
  ui/           # 角色窗口、气泡、菜单、设置、关于与首次提示
resources/      # Qt 资源清单和项目自制 UI 资源
third_party/    # Ark Pixel 字体、OFL 文本和来源说明
tests/          # Qt Test；目录结构与生产职责对应
packaging/      # AppImage、Windows ZIP、desktop 文件和发行元数据
```

依赖方向：

```text
app → ui → character/dialogue/core
app → platform
ui  → platform 的抽象接口
core 不依赖 Widgets、Win32、XCB 或 D-Bus
```

正式构建至少产生：

- `money-under-bed-core`：可脱离桌面的纯逻辑库。
- `money-under-bed-deskpet`：Qt Widgets GUI 可执行文件。
- 若干按职责拆分的 Qt Test 测试目标。

不为每个小类创建独立库；只有确实需要隔离平台或脱离 GUI 测试的边界才拆分目标。

## 10. 阶段 5：统一事件调度、单击、拖动与投喂

事件优先级是本阶段的架构核心，必须先于各互动独立扩张。

### 10.1 事件协调器

- [x] 定义退出／隐藏、投喂、连续对话、单击反馈和自主闲聊事件类型及统一优先级。
- [x] 所有行为请求只提交给协调器，由协调器决定接受、替换或抑制；功能模块不能直接强制切换全局状态。
- [x] 不建立延迟事件队列；被抑制或替换的低优先级事件不会补播。
- [ ] 隐藏清除当前对话页面；退出直接结束。协调器侧已具备（`Shutdown` 优先级最高，`clear()` 无条件清空），但「隐藏」菜单项属于阶段 7，届时接上即可勾选。
- [x] 对外暴露可观察状态，便于日志和确定性测试。

### 10.2 输入手势

- [x] 基于移动距离阈值区分单击与拖动；按下时不提前计为单击。
- [x] 拖动保持当前画面，松手后按底部距离决定停留或返回。
- [x] 没有连续对话时，单击从当前状态允许的动作／表情／台词反馈中选择。
- [x] 气泡关闭或安静模式下仍保证非文字反馈。

### 10.3 投喂

- [x] 右键菜单的临时测试入口触发吃冰淇淋动画。
- [x] 按内部概率选择正常吃或掉落事件；概率可通过测试注入强制分支。
- [x] 投喂进行中忽略新的投喂请求，不排队、不重播。
- [x] 掉落事件结束后进入对应连续对话，不让自主闲聊插入。

### 自动检查

- [x] 优先级任意两事件组合的表驱动测试。
- [x] 连续多事件到达时最终状态和无队列测试。
- [x] 单击／拖动阈值边界测试。
- [x] 投喂正常、掉落和重复请求测试。

### 退出门

- 正式代码只有一个全局行为仲裁入口。
- 快速连续点击、投喂和自主触发不会产生重叠动画、滞后台词或不可恢复状态。
