# 1.1 正式候选验收清单

本表只用于 `v1.1.0` 标签生成的草稿 Release。开发版 artifact 可以做回归，但不能
代替这里的最终结果；验收通过后直接发布草稿中的原文件，不重新构建。

`1.0` 的清单是 `docs/ReleaseChecklist-1.0.md`，已停用，只作历史记录。本表相对它
的实质变化有三处，都有决策依据：

- 第 1 节不再有「Windows window probe 全绿」。该工作流只构建 `probes/window/`，
  不监听标签，已于 `1.1.0` 阶段 5 删除。
- 第 3 节的 Windows **不要求连续运行三小时**，依据是 `docs/Decisions.md`
  第 14.10 节对第 11.3 节的显式放宽。放宽只针对运行时长，其余项目一项不减。
- 第 4 节的性能数据**不换算成数值门槛**，依据同样是第 14.10 节：如实记录，
  由项目所有者判定「通过／不通过」。

## 2. KDE Plasma + XCB/XWayland

记录发行版、Plasma、会话、分辨率、系统缩放、GPU 与驱动。

### 2.1 `1.0` 已有范围的回归

- [ ] AppImage 直接启动，首次提示与应用菜单入口正常。
- [ ] 透明、像素命中、置顶、焦点、任务栏、拖动和自主移动正常。
- [ ] 四向动画、待机／跑动切换、投喂和事件优先级正常。
- [ ] 气泡视觉、打字、翻页、表情、跟随和边界夹取正常。
- [ ] 托盘隐藏／唤回、第二实例唤回和强杀后重启正常。
- [ ] 锁屏／解锁、睡眠／唤醒、显示关闭／恢复后不突进、不留虚影。
- [ ] Plasma Shell 重启、屏幕可用区域变化后窗口仍可见且可退出。
- [ ] 项目显示倍率 `1×`、`2×`、`3×` 均实际检查。

### 2.2 应用生命周期（第 14.6 节，`1.0` 候选的已知缺陷）

- [ ] 关闭设置窗口后程序继续运行，角色仍在。
- [ ] 关闭关于窗口后程序继续运行，角色仍在。
- [ ] 设置与关于窗口都关闭、角色处于隐藏状态时，程序仍在托盘中存活。
- [ ] 反复开关设置与关于窗口各若干次后，两者仍是同一个实例，取值保持。
- [ ] 托盘「退出」是唯一退出路径；退出前未落盘的修改被写入配置文件。

### 2.3 设置界面与生效边界（第 14.2、14.8 节）

- [ ] 四个分组齐全，每组的「高级」折叠区能展开收起。
- [ ] 成对上下限只有数字框，没有滑块；其余滑块都配有数字框。
- [ ] 数字框输入多位数的中间值不生效、不落盘（例如输入 `3000` 不触发 `3`）。
- [ ] 拖动滑块时立即生效；松手后才落盘。
- [ ] 改动任一高级参数后，对应档位显示「自定义」。
- [ ] 七组档位逐档切换，实际行为随之改变。
- [ ] 「恢复本组默认值」只影响本组，确认框显示组名，取消后无任何变化。
- [ ] 「全部恢复默认值」影响四组，取消后无任何变化。
- [ ] 时长、速度类改动只影响**下一次**行为，不打断进行中的动作。
- [ ] 重启后全部取值保持（schema 1）。
- [ ] `--scale N` 只覆盖本次运行；随后在界面改设置并重启，配置文件中的倍率
      仍是命令行之前的值。

### 2.4 自主闲聊（第 14.4 节，`1.1.0` 新增）

- [ ] 说话频率「关闭」时不再出现自主闲聊；单击台词不受影响。
- [ ] 低／中／高三档的自主闲聊频次有可感知差异，最高档仍不构成高频陪聊。
- [ ] 安静模式下不出现自主闲聊。
- [ ] 暂停、隐藏、会话挂起期间不出现自主闲聊；恢复后不补播积压。
- [ ] 单击台词概率与说话频率互不影响。
- [ ] 高级层把触发概率单独改成 `0` 后界面显示「关闭」，原间隔仍保留在配置里。

## 4. 性能记录（不设数值门槛）

按 `docs/Decisions.md` 第 14.10 节：本节数据是观察材料，不是自动判定门槛。
占用是否可接受由项目所有者判断，结论以「通过／不通过」写入验收记录与
Release 说明，不换算成固定预算数字。

KDE 连续运行三小时；Windows 记录启动时间与一次常规使用后的占用即可。期间正常
触发移动、气泡、投喂、设置、隐藏和一次生命周期恢复，不只静置。

**采样方式**（`1.1.0` 人工检查点 A 的教训，见 `docs/Plans/DevelopmentStatus-1.1.md`）：

- CPU **不要用 `ps` 的 `%cpu`**——它是进程存活期的累计平均，对定时器驱动的动画
  进程系统性偏低，检查点 A 的 5 分钟采样因此得到几乎全为 `0.00` 的一列废数据。
  Linux 用 `pidstat -p <PID> <间隔>`，或对 `/proc/<PID>/stat` 的 `utime`＋`stime`
  求两次差值。
- 磁盘读写若取 `read_bytes`／`write_bytes`，只统计落到块设备的 I/O，配置写入停在
  页缓存里看不到，不能据此判断有没有落盘。
- 记录连续均值，不只记三个时间点的瞬时值。

## 5. 如实保留的边界

- [ ] 没有合格 GNOME 社区结果时，继续标为实验性／未验证。
- [ ] 多显示器、热插拔和混合 DPI 未实测，不写成已支持。
- [ ] niri 与原生 Wayland 不进入正式支持范围。
- [ ] README 与 Release 说明明确非官方、非商业二创、素材限制、字体 OFL、
      项目 GPL，以及 Windows 未签名风险。
- [ ] 素材的 R18 禁止与不作为图像生成 AI 训练数据的限制在包内和说明中保留；
      对外只引用 `readme.txt` 的书面条款。
